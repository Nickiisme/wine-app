# 品鉴时间与记录生命周期验证（2026-10-17）

## 本次已实现

- 普通品鉴页顶部的日期入口，默认今天；今天/昨天快捷选择、具体日期、非法日期与未来日期拦截。
- `tasted_on` 保存用户选择的日历日期，`tasted_at` 保留兼容时间戳，`created_at` 保持录入时间。日期字段不随查看时区改变。
- 时间线、最近品鉴、饮酒日历、徽章达成日期使用实际品鉴日期；同品种不同风土/新旧世界的达成日期仅考虑截至当日的记录。
- 编辑酒款信息、日期、评价、风味、笔记和照片；未改变字段保留 provenance。使用 `updated_at` 检测并发编辑，保留 creation time 和藏酒关联。
- 确认软删除后乐观移出页面；失败恢复；云端普通查询排除 `deleted_at` 非空的记录。头像页、足迹、画像、徽章随当前记录集合重算。
- 数据层恢复接口与数据库30天恢复窗口；尚无面向用户的回收站。
- 藏酒徽章使用最早藏酒创建日期，不再每次渲染生成新获得日期。

## 数据库部署依赖（尚未执行）

执行 `prototype/cloudbase/postgresql-record-lifecycle.sql`，前提是已有品鉴、metadata、cellar 表与迁移。

该脚本添加日期/删除字段、时间索引与生命周期 trigger，保留已有记录；撤销客户端物理删除品鉴记录的权限。SQL 未在真实 PostgreSQL/CloudBase 环境执行，RLS 和 trigger 需要测试环境验证。

历史记录没有原始时区：一次性按 Asia/Shanghai 将已有 tasted_at（其次 created_at）转换为 tasted_on。这是明确的兼容假设，并不能恢复历史上未记录的真实喝酒时间。已存在的 tasted_on 不会被覆盖。

迁移未部署时：只有确认 deleted_at 列缺失，才允许旧结构的只读查询回退；网络和权限失败不允许绕过软删除过滤。新增/编辑/删除会明确提示迁移依赖，不假装保存成功。

## 仍未完成，不能宣称上线

1. 云端迁移部署和真实权限测试：缺少本会话可用的 PostgreSQL 管理连接/独立测试账号；仓库此前兼容性报告也未完成业务环境验证。
2. 30天自动永久清理：目前仅有软删除和恢复期限；没有上线的定时 worker。不能向用户承诺到期自动清除。照片需同时检查品鉴记录、软删除恢复窗口内记录及藏酒的所有引用，再由存储 API 删除；不能直接删除 storage 元数据充当文件删除。
3. 清除所有个人数据：尚未实现后端事务、存储清理及分享失效流程，因此未增加假成功入口。
4. 注销账户：尚未验证 CloudBase 身份删除管理接口和二次身份校验。需要有权限的服务端执行并处理部分失败及重试；不得用退出登录代替注销。
5. 照片编辑移除仅断开记录引用；本次保留存储文件，待后台无引用清理任务接入。上传成功后记录写入失败可能留下孤立文件，也需后台清理。
6. 真实云端上线验收：分别验证本人修改、越权失败、30天内恢复、超期拒绝、重复请求、私有图片引用、删除品鉴不改变库存。
